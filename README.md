## Overview

This project implements a context-aware travel recommendation system designed to surface "off-the-beaten-path" destinations. Unlike traditional recommendation engines that favor popular tourist spots, our system identifies hidden gems by analyzing travel blogs, structured attributes, and popularity signals to recommend lesser-known destinations that match user interests.

The application combines:

- **BM25 Baseline Search**: Traditional information retrieval over a corpus of travel blogs, indexed in memory at API startup
- **ModernBERT Semantic Search (FAISS)**: Semantic retrieval and re-ranking using transformer-based text embeddings from blog content, enabling contextual understanding beyond keyword matching
- **Optional LLM Explanations**: Natural-language explanations for the top results, generated by DeepSeek-V3 via the Hugging Face Inference API

The frontend (Streamlit) and backend (FastAPI) are deployed as separate Hugging Face Spaces, with blog metadata stored in an AWS RDS PostgreSQL database and precomputed ModernBERT embeddings stored in an AWS S3 bucket. Docker and Docker Compose are provided for local development and reproducibility.

## Project Components

### Data Collection & Storage

Blog data is collected offline via `backend/data_collection/collect_blog_posts.py` and loaded into cloud storage ahead of time:

- **Discovery**: Candidate travel blogs are found via SerpAPI Google searches (e.g. WordPress travel blogs about Japan/Greece), and each blog's sitemap is crawled to enumerate individual post URLs.
- **Scraping**: Post content is fetched with `requests`/`BeautifulSoup`, cleaned, and paired with page metadata (title, description, author) pulled from meta tags.
- **Geocoding**: spaCy NER extracts a candidate place name (GPE/LOC entities) from each post's title/description, which is then geocoded to latitude/longitude via ArcGIS (through `geopy`).
- **Storage**: Cleaned posts, metadata, and coordinates are written to an AWS RDS PostgreSQL database (`travel_blogs` table) via SQLAlchemy, with duplicate URLs skipped on conflict.
- **Embeddings**: ModernBERT embeddings of blog content are precomputed separately and stored in an AWS S3 bucket, from which they're loaded into memory by the API at startup for FAISS-based semantic search.

### BM25 Baseline Search
BM25 (Best Match 25) is a ranking function used by search engines to estimate the relevance of documents to a given search query. Our implementation:

**How It Works:**
- Loads the blog corpus from the AWS RDS PostgreSQL database
- Tokenizes and indexes content using `rank-bm25`
- Index is preloaded once at API startup (via a FastAPI startup event) so searches are fast
- Returns top-k most relevant destinations based on query terms, along with blog metadata (title, author, URL)

### ModernBERT Semantic Search Model (FAISS)

A transformer-based semantic retrieval and re-ranking model that captures the meaning of user queries and travel narratives, enabling discovery of destinations that align with "off-the-beaten-path" intent beyond surface-level keyword overlap.

**How it Works**

- Blog content is encoded offline using ModernBERT transformer embeddings; the resulting vectors are stored in AWS S3
- At API startup, embeddings are loaded from S3 into memory and indexed with FAISS
- User queries are encoded into the same semantic vector space
- FAISS retrieves and ranks destinations by embedding similarity (distance), optionally combined with lightweight metadata filters (e.g., geography, experience type)

**Model Capabilities:**

- Understands experiential intent (e.g., quiet, local, remote, authentic) from natural language
- Captures contextual cues implicitly through embeddings rather than hand-crafted rules
- Handles synonymy and paraphrasing (e.g., "hidden village" ≈ "undiscovered town")
- Robust to sparse or ambiguous queries

**Outputs:**

- Ranked list of destinations with a semantic distance score
- Associated blog metadata (title, author, URL, excerpts)
- Destination coordinates for downstream visualization

### Optional LLM Explanations

When enabled via a sidebar toggle in the Streamlit app, the API calls DeepSeek-V3 (`deepseek-ai/DeepSeek-V3-0324`) through the Hugging Face Inference API to generate a short natural-language explanation of why each of the top 3 destinations matches the user's query, based on the retrieved blog content.

### Architecture

**Production Deployment (Hugging Face Spaces):**

- **Frontend Space**: Hosts the Streamlit UI, calling the backend API over HTTPS
- **Backend Space**: Hosts the FastAPI service, which loads the BM25 index from RDS and the FAISS index from S3 at startup, and proxies LLM explanation requests to the HF Inference API

**Local Development (Docker Compose):**

Two containers are orchestrated locally, both pointing at the same cloud-hosted data:

**Frontend (Streamlit)**
- Port: 8501
- Framework: Streamlit
- Purpose: Interactive web UI for search and visualization
- Talks to the backend via the `API_URL` environment variable (defaults to the hosted Hugging Face Space if unset)

**API Layer (FastAPI)**
- Port: 8000 (mapped to 8081 on host)
- Framework: FastAPI
- Purpose: Serves BM25 and FAISS/ModernBERT search, plus `/stats` and `/health` endpoints

**Data Layer (Cloud, not containerized)**
- **AWS RDS (PostgreSQL)**: Stores blog posts, locations, coordinates, and metadata; connected via the `DATABASE_URL` environment variable
- **AWS S3**: Stores precomputed ModernBERT embeddings used to build the FAISS index at startup

## Docker Deployment Instructions

### Building and Starting Containers

**1. Clone the Repository:**
```bash
# Clone the project repository
git clone https://github.com/dcorc7/Travel-Recommender.git

# Navigate to project directory
cd Travel-Recommender
```

**2. Set Up Environment Variables:**

Create a `.env` file in the project root with your database and cloud connection info:

```env
DATABASE_URL=postgresql://user:password@your-rds-endpoint:5432/database
AWS_ACCESS_KEY_ID=your_access_key
AWS_SECRET_ACCESS_KEY=your_secret_key
AWS_S3_BUCKET=your-embeddings-bucket
HF_API_TOKEN=your_huggingface_token
API_URL=http://api:8000
```

**3. Build and Start All Services:**

```bash
# Build images and start containers
docker-compose up --build

# OR run in detached mode (background)
docker-compose up --build -d
```

**What This Does:**

- Builds the API container from `backend/Dockerfile.api`
- Builds the Streamlit container from `frontend/Dockerfile.streamlit`
- Creates a Docker network for inter-container communication
- Starts both services with proper dependency ordering
- Mounts source directories for hot-reloading during development

**4. Wait for Services to Initialize:**

On startup, the API loads the BM25 corpus from AWS RDS and builds the in-memory index, and loads the ModernBERT embeddings from AWS S3 to build the FAISS index. This takes approximately 30-60 seconds depending on corpus size and network speed.

### Accessing the Applications

Once containers are running:

**Travel Recommender Web Interface:**

- Local: http://localhost:8501
- Hosted: Streamlit frontend Hugging Face Space
- Opens the Streamlit application in your browser; search for destinations and view recommendations

**API Documentation:**

- Local: http://localhost:8081/docs

## Using the Travel Recommender

### Step 1: Access the Web Interface

Open your browser and navigate to http://localhost:8501 (local) or the hosted Streamlit Space URL.

### Step 2: Describe What You're Looking For

The sidebar collects three free-form text fields, which are combined into a single query:
- **General destination description** (e.g., "small coastal towns with artisan markets")
- **Activities of interest** (e.g., "local performances, museums, unique foods")
- **Desired geography** (e.g., "coastal, mountain, urban, forest")

### Step 3: Configure Search Parameters

- **Number of Search Results**: how many destinations to return (3-50)
- **Generate LLM Explanations**: toggle DeepSeek-V3-generated explanations for the top 3 results on/off
- **Retrieval Model**: choose between **BM25** (keyword search) and **FAISS** (ModernBERT semantic search)

### Step 4: View Results

The application returns results across several tabs:

**Results Tab:**

- Ranked list of destinations with score (BM25) or distance (FAISS)
- Destination name and country
- Blog snippets
- Link to the source blog post and a full scoring/metadata breakdown

**Maps Tab:**

- Interactive global map with destination markers, color-coded by relevance (score or distance)

**Explanations Tab:**

- DeepSeek-V3-generated explanations for the top 3 destinations, when enabled

**Database Stats Tab:**

- Live counts of total posts, unique locations, blogs, and authors from AWS RDS
- Geographic distribution map of the full corpus, color-coded by post density

**About Tab:**

- Overview of the system, data sources, and team

## API Usage

You can also interact directly with the API (local or hosted Hugging Face Space):

### Search Endpoint

**BM25 Search:**

```bash
curl -X POST "http://localhost:8081/search" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "temples in Kyoto Japan",
    "retrieval": {
      "model": "bm25",
      "k": 10
    },
    "llm_explanations": false
  }'
```

**ModernBERT Semantic Search (FAISS):**

```bash
curl -X POST "http://localhost:8081/search" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "quiet coastal villages with local markets",
    "retrieval": {
      "model": "faiss",
      "k": 12
    },
    "llm_explanations": true
  }'
```

### Response Format

```json
{
  "query": "quiet coastal villages with local markets",
  "params": {
    "retrieval": {
      "model": "faiss",
      "k": 12
    },
    "model_used": "faiss"
  },
  "results": [
    {
      "destination": "Ninh Binh",
      "country": "Vietnam",
      "lat": 20.25,
      "lon": 105.9,
      "distance": 0.1342,
      "snippets": [
        "A quiet region of limestone karsts and river villages.",
        "Local markets operate daily with minimal tourism."
      ],
      "full_content": "Full blog text...",
      "why": {
        "model": "FAISS",
        "page_title": "Hidden Northern Vietnam",
        "page_url": "https://example.com/blog/post",
        "blog_url": "https://example.com",
        "author": "Travel Blogger"
      }
    }
  ],
  "explanations": [
    "This destination aligns with your query due to its emphasis on quiet local villages and authentic market culture..."
  ]
}
```

### Other Endpoints

- `GET /health` — reports whether BM25 and FAISS search are available
- `GET /stats` — returns total posts, unique locations/blogs/authors, and grouped coordinates from AWS RDS

## Development

### Data Collection (Re-populating the Corpus)

To discover new blogs, scrape posts, geocode locations, and write them into AWS RDS:

```bash
python ./backend/data_collection/collect_blog_posts.py
```

This requires a SerpAPI key (`API_KEY`) and a valid `DATABASE_URL`. *Note:* ModernBERT embeddings for any newly collected posts must be generated and uploaded to the S3 bucket separately for them to be searchable with FAISS.

## Deployment Notes

- The frontend** and **backend are each deployed as their own Hugging Face Space; the Streamlit app's `API_URL` defaults to the hosted backend Space when not overridden locally.
- The backend loads all search indices at startup (the BM25 corpus from AWS RDS and the FAISS/ModernBERT embeddings from AWS S3) so a cold start on Spaces can take longer than local Docker startup.
- LLM explanations depend on the Hugging Face Inference API and DeepSeek-V3 being reachable; if that call fails, the API falls back to returning `"Explanation unavailable."` for the affected result rather than failing the whole request.
